# Track A-2 — 코인원 현물 롱온리 순환매

A-2의 실거래 실행기는 구현되어 있다. 다만 저장된 운영값은 **paused / observe / execution disabled**이고 허용 종목도 비어 있다. 코드가 있다는 사실과 실거래 승인은 별개다. 이 상태에서 `python -m track_a_2.live`를 실행하면 인증정보를 읽거나 상태 디렉터리를 만들기 전에 중단된다.

## 전략 계약

A에서 다음 순환매 계약만 명시적으로 이어받는다.

- 코인원 KRW 현물에서 롱만 운용한다. 숏·레버리지·마진·펀딩 규칙은 없다.
- 하락 움직임의 감속이 확인될 때만 진입·추가하고, 직전 매수보다 유리한 사다리 간격을 지킨다.
- 반등 움직임이 정체될 때 덜며 새 로트의 원가와 실제 왕복 수수료를 게이트에 반영한다.
- 마지막 물량도 정체에서 정리할 수 있다. 영구 코어는 없다.
- 자격 순위가 내려갔다는 이유만으로 보유 종목을 갈아타지 않는다. 유동성·거래상태 자격을 잃으면 추가 매수를 멈추고 기존 청산 규칙으로 비운다.

Bitget A의 USDT 숫자, 롱·숏 대칭, 레버리지, 선물 보호주문은 상속하지 않는다. `common.signal`의 순수 신호·상태 전이만 사용하고 수량, 원화 손실한도, 종목 선정, 호가단위와 체결은 코인원용 경계에서 다시 계산한다.

기본 위험 상한은 포트폴리오 평가액 대비 유닛 5%, 종목당 명목 20%, 전체 명목 60%, 종목당 손실예산 0.5%, 일 손실 2%다. 실제 주문 수량은 이 상한에 더해 가용 원화, 상위 5호가 매도 깊이의 10%, 거래소 최소·최대 주문과 수량단위 중 가장 작은 값으로 정한다. 이 숫자는 활성화 승인이 아니라 초기 후보값이다.

## 종목 순환

`config.json`의 명시적 `universe`만 후보가 된다. 거래 가능 상태, 점검 상태, 지정가·시장가·예약가 지원, 24시간 원화 거래대금, 변동폭과 스프레드를 통과한 종목을 거래대금×변동폭으로 정렬한다. 이미 선정된 적격 종목은 유지하고 빈 자리만 순위로 채운다. 보유 중 탈락한 종목은 `wind_down`으로 바뀌며 신규·추가 매수만 차단된다.

현재 `universe=[]`은 의도적인 잠금이다. 검증되지 않은 종목을 코드가 임의로 고르지 않는다.

## 주문과 복구 계약

- 주문 식별자는 전 거래쌍에서 유일한 `ta2-...`만 사용한다. 전송 전 SQLite에 의도를 완전 동기화하고, 응답을 잃은 주문은 같은 식별자로 조회할 뿐 재주문하지 않는다.
- A-2는 `BUY LIMIT post_only`, `SELL MARKET`, `SELL STOP_LIMIT`만 실행한다. 출금·이체 API는 구현하지 않았다.
- 누적 체결수량·평균가·수수료는 단조롭게 한 번만 장부에 반영한다. 취소 응답만으로 자금이나 수량을 해제하지 않고 주문 상세를 다시 확인한다.
- 모든 보유수량에는 가능한 즉시 코인원 `STOP_LIMIT`을 둔다. 프로세스 종료 시 신규 매수와 청산 중 주문을 취소·대사하고 네이티브 보호주문만 남긴다.
- 코인원에는 원자적 OCO가 없으므로 장시간 매도 지정가와 전체수량 보호주문을 동시에 두지 않는다. 정체 매도는 보호주문 취소·체결 대사 뒤, 기존 손절 지정가를 하한으로 둔 시장가 매도로 즉시 전환한다. 손절 지정가 아래로 갭이 나거나 발동 후 2초간 남으면 보호주문을 취소·대사한 다음 잔량을 가격 제한 없는 시장가로 정리한다.
- 부분 매수체결은 잔여 매수를 먼저 취소한다. 남은 수량이 거래소 최소금액 아래여서 보호·매도가 불가능하면 `UNSELLABLE_RESIDUAL`로 멈추며, 거래를 늘리거나 최소금액을 우회하지 않는다.
- 계좌의 알 수 없는 주문·코인, 장부 대비 수량·원화 불일치, 예상보다 큰 수수료, 낡은 계좌 스냅샷, 저장공간 부족은 신규 진입을 차단한다. 기존 포지션의 보호·축소·청산은 계속 허용한다.

## 자본과 소유권

A-2는 C와 다른 코인원 포트폴리오 및 API 키만 사용한다. 환경변수 이름도 `COINONE_A2_ACCESS_TOKEN`, `COINONE_A2_SECRET_KEY`로 분리되어 있고 C 키로 대체되지 않는다. 사용자가 정한 자본 계획은 C 포트폴리오에 20,000원을 남기고 나머지를 A-2 포트폴리오로 옮기는 것이다. 이 구현 작업은 포트폴리오 생성, 자산 이동, 키 발급, 실주문을 수행하지 않았다.

A-2 포트폴리오에는 A-2가 소유하지 않은 코인이나 주문이 없어야 한다. C의 원화 장부, `tc-...` 주문, 잔여 코인, 모델·평가·상태 파일을 읽어 A-2 자본으로 채택하지 않는다. 별도 포트폴리오는 포트폴리오 간 동시 반대 주문으로 생길 수 있는 자전거래도 운영 단계에서 피해야 한다.

## 실행 잠금

실거래 시작에는 다음 조건이 동시에 필요하다.

1. 코인원에서 C와 분리된 A-2 포트폴리오를 만들고 자본을 배정한다.
2. 그 포트폴리오에만 연결되고 잔고조회·주문조회·주문관리 권한과 고정 IP 제한을 가진 전용 키를 `.env`에 넣는다.
3. 코인원 녹화 테이프의 시간순 재생·비용 스트레스를 통과한 종목만 `universe`에 명시하고 `a2-eval-...` 평가 식별자를 정한다.
4. `track_a_2/config.json`에서 `status=active`, `mode=live`, `execution_enabled=true`, `portfolio_isolation_confirmed=true`, 승인 식별자와 고정 출구 IPv4를 함께 설정한다.
5. `config/tracks.json`의 A-2도 별도로 `status=active`, `execution_enabled=true`로 바꾼다.
6. 레포 및 A-2 상태 디렉터리에 `STOP`·`PAUSE`가 없음을 확인한다.

각 매수 주문은 3~6번을 HTTP 바이트 송신 직전 다시 검사한다. 실행 중 `PAUSE`는 새 매수만 막고 보호·축소는 유지한다. `STOP`은 신규 매수와 진행 중 정체 매도를 정리하고 보유분의 거래소 보호주문을 확인한 뒤 프로세스를 끝낸다. 실행기나 감독자는 자동으로 시작되지 않는다.

```powershell
# 로컬 설정과 잠금만 확인한다. 키와 네트워크를 사용하지 않는다.
python -m track_a_2.live --check

# 상태를 읽기 전용으로 확인한다.
python -m track_a_2.status

# 모든 운영 조건을 사람이 충족시킨 뒤에만 실행된다.
python -m track_a_2.live --config track_a_2/config.json
```

## 디렉터리 경계

| 경로 | 역할 |
|---|---|
| `market/` | 코인원 KRW 종목·호가·체결·캔들, 바구니 자격과 단위 반올림 |
| `strategy/` | 자본·호가깊이·거래소 한도를 함께 적용한 현물 수량 산정 |
| `execution/` | A-2 전용 인증·주문 허용목록, 사전점검, 장부, 부분체결·재시작 대사 |
| `runtime.py` | 공개·개인 웹소켓, REST 직렬화, 전략과 OMS 조정, 안전 종료 |
| `replay/` | 향후 코인원 녹화 테이프 재생 전용 경계 |

코드와 회귀 테스트만 레포에 둔다. 공개 피드 녹화, 계약 스냅샷, SQLite 장부와 상태는 정확히 `../trading-room-state/track-a-2/`에 둔다. 다른 트랙 경로나 레포 내부 경로는 설정 검증에서 거부한다.
