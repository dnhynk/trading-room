# 트랙 C — 코인원 현물, 선행거래소 공정가 기준 규칙형 메이커 (C3)

C3가 현재 계약이다. C2(학습형 정책)는 2026-09-05 감사(`track_c/AUDIT-20260905.md`)로 폐기됐고 그 코드는 비교·재생용으로만 남는다. A/B는 일시정지 상태이며 이 문서와 문장을 상속하지 않는다.

## 가설과 근거

코인원은 업비트·빗썸을 5~30초 후행한다. 30분 동시 녹화에서 `공정가 − 코인원 중간가`와 다음 30초 중간가 변화의 상관은 XRP 0.38, BTC 0.35, ETH 0.35, SOL 0.33이고 5분 블록 전부 같은 부호였다. 코인원 최우선 매수호가는 공정가가 그 아래로 내려간 순간에만 채워지므로(무조건 대기는 모든 종목에서 음수), 공정가 위에 있을 때만 걸고 아래로 내려가면 거두는 규칙이 역선택을 제거한다. 양의 기대값은 아직 미입증이며 사전 등록한 판정(아래)으로만 확정한다.

## 공정가 산식 (`track_c/fair.py`)

이론: 여러 거래소의 같은 자산 로그가격은 하나의 랜덤워크 효율가격을 공유하고 공적분 벡터 (1, −1)과 느리게 변하는 상수(거래소 간 프리미엄)로 묶인다(Engle–Granger 1987). 조정하는 쪽은 후행 거래소이므로 공통요인 가중치는 선행 거래소에 놓인다(Hasbrouck 1995 정보지분, Gonzalo–Granger 1995 영구-일시 분해). 편차는 VECM 오차수정항이다.

- 선행 거래소 i의 가격 `M_i` = 마이크로프라이스(Stoikov 2018 1차 근사, 잔량가중 mid) `(ask·bid_qty + bid·ask_qty)/(bid_qty+ask_qty)`. 설정 `leader_price: mid`로 단순 mid 변형을 둔다.
- 프리미엄 상수 `r̂_i` = 과거 300초 동안 1초마다 표본한 `coinone_mid / M_i`의 중앙값. 현재 초의 표본은 제외한다(미래 미사용). 표본 60개 미만이면 사용하지 않는다.
- 공정가 `F = Σ w_i · M_i · r̂_i / Σ w_i`, 30초 이내 갱신된 선행 거래소만 포함. 기본 가중치는 등가중이며 `track_c/fairfit.py`가 조정계수 α·반감기·GG 가중치·정보지분 구간을 추정한다. 비등가중은 다일 녹화에서 사전 등록 변형으로 평가한 뒤에만 채택한다.
- 편차 `dev = (F − coinone_mid) / tick`(틱 단위).

30분 창의 추정(빗썸 기준): 코인원 조정계수 α ≈ −0.055/초, 편차 반감기 BTC 12.7초·XRP 12.4초·ETH 24.9초·SOL 44초. 마이크로프라이스의 일시 잡음 때문에 정보지분 추정은 30분 표본에서 불안정하므로 가중치 결정 근거로 쓰지 않는다.

## 규칙 (`track_c/rule.py`, 모두 사전 등록 값)

| 단계 | 규칙 |
|---|---|
| 종목 | BTC·ETH·XRP·SOL 고정. 스프레드가 2틱 초과이면 진입 없음 |
| 진입 | `dev ≥ 0`이면 최우선 매수호가에 post-only 지정가, 1만 원 명목(최소 격자), TTL 60초. 종목당 한 캠페인 |
| 취소 | 대기 중 `dev < −0.5틱` 또는 공정가 불가이면 취소 |
| 익절 | 체결 즉시 `진입가 + 1틱`에 post-only 지정가 매도를 걸어 둔다(거래소 스탑과 동시 보유 불가, OCO 없음) |
| 방어 | `dev < −0.5틱`이면 익절 주문 취소 후 시장가 매도 |
| 손절/시간 | 매수호가 ≤ 진입가 − 3틱 또는 첫 체결 후 180초 |
| 잔량 | 최소 주문액 미만 잔량은 원가와 함께 `residuals`로 이월해 같은 종목의 다음 캠페인에 합친다. 포트폴리오 HALT 없음 |

Avellaneda–Stoikov(2008)의 유보가격 관점에서 재고는 최대 1단위이므로 유보가격 이동은 무시하고, Glosten–Milgrom(1985)의 역선택 비용은 `dev ≥ 0` 게이트가 대신한다. 위험 한도(회당 0.25% W, UTC 일일 1.5%)와 계정·소유권·알림 규칙은 유지한다.

## 판정 (사전 등록)

`track_c/c3_replay.py`가 녹화(코인원 `data/public`, 선행 `data/leaders`)에 같은 코드로 규칙을 재생한다. 지표는 서로 다른 체결 이벤트(캠페인)와 KST 일별 블록이며, 대조군은 부호 반전(`--control flip`)과 무조건 대기(`--control unconditional`)다. 채택 기준: BTC 캠페인 평균 순손익 > 0, 90% 하한 > 0, 5거래일 중 4일 이상 양수. 미달이면 HOLD이고 규칙을 사후 조정하지 않는다. 변형은 `entry_ticks +0.5`, `leader_price mid`, `leader_weights`(fairfit 추정) 세 가지뿐이며 같은 기준으로 본다. 확대는 채택 후 1분 매도 대금의 10% 이하 참여율까지만.

최소 크기 실거래는 판정 전에도 허용된 실행 표본 수집이다(사용자 승인 2026-09-05). 체결당 손익 ±1틱(≈1원)이며 수익 증거가 아니다.

## 실행 불변식

- 한 writer(`data/ledger.sqlite`), 전송 전 의도 저장, 누적 체결 차분, 취소 후 재조회, 응답 유실 시 재제출 금지. 계정 잔고 전체가 운용자본이며 입출금은 손익에서 분리한다.
- C3 엔진(`track_c.c3_runner`)이 코인원 공개 데이터와 선행거래소 호가를 직접 녹화한다. 엔진이 내려간 동안만 `trading-room-c-leaders.service`를 따로 돌린다. 둘을 동시에 돌리지 않는다.
- 신선도: 코인원 호가는 변경 시에만 푸시되므로 보유 중 판단은 연결 생존(60초 이내 마지막 호가)으로, 신규 진입은 1.5초 이내 호가로 한다.
- 알림은 기존 독립 릴레이(`bot.notify` C 경로)를 유지한다. 청산 사유 `take_profit`·`defend`·`stop`·`dust`·`take_rejected`는 `track_c/notices.py`가 해석한다.
