# 국내 현물과 짧은 감속 스캘핑

새 정책은 **국면 방향으로 움직이는 코인의 일시적 반대 움직임이 감속할 때 한 번 진입하고, 반등의 끝·전제 파괴·시간 만료 중 먼저 오는 것으로 청산**한다. 가격 목표를 예측하는 모델은 쓰지 않는다. 그 사실만으로 수익 알파가 생기는 것은 아니다. 첫 진입 문턱의 후속 대조와 BTC·ETH/바구니 선정 판단은 [ENTRY-REVIEW-20260905.md](ENTRY-REVIEW-20260905.md)에 있다. 아래 진입 세 조건은 기본안이며 후속 대조는 config에 조건을 명시한다.

## 정확한 진입과 청산

- 진입: 기존 `Features`의 속도 감속 신호, 최근 10초 공격 체결 방향 반전, 밀어붙이던 거래량 감쇠를 모두 요구한다. 10초 실제 체결이 3건 미만이면 진입을 허용하지 않는다. 최근 체결이 없는 코인을 거래량 소멸로 오인하지 않기 위한 첫 실험 가설이다.
- 국면: 기본 후보는 마감 15분·1시간 봉의 확인된 구조 방향이 모두 포지션과 같을 때만 진입한다. 미래 봉은 읽지 않으며 이력이 부족하거나 방향이 불명확하면 대기한다. 별도 필터 없는 대조군도 함께 실행한다.
- 주문: 호가에 지정가로 한 유닛만 둔다. 가격을 쫓아 체결을 만들지 않는다. `scalp`는 주문 의도가 만들어진 후 5초에 취소 요청한다. 취소 확인까지는 체결될 수 있고, 그때 생긴 포지션도 청산 경로가 이어진다.
- 무효화: 진입 신호 당시 저점/고점에서 해당 가격대 호가 단위 두 개 바깥을 경계로 동결한다. 실행 방향의 호가가 경계를 넘어가고 공격 체결 방향도 다시 불리해진 상태를 **서로 다른 연속 마감 초 두 개**에서 확인하면 전량 청산을 요청한다. 한 틱 반전이나 거래 공백만으로 무효화를 확정하지 않는다.
- 시간: **첫 부분체결부터 60초**다. 뒤늦은 부분체결이 시계를 연장하지 않는다. 새 신호가 없고 해당 종목의 메시지가 끊겨도 시한은 만료된다.
- 반등 끝: 반대편 속도 정체가 나오면 비용 게이트 없이 청산한다. 진입 원가를 회복할 때까지 기다리지 않는다.
- 보호막: 기존 돈 한도 스탑과 위험 상한을 유지한 시뮬레이션이다. 짧아진 무효화 경계로 수량을 역산해 늘리지 않는다. 명목 0.75W·기본 손실 예산 0.05W·15ATR1m 크기 제한·공유 캠페인 하나를 유지한다.

5초·60초·두 호가·두 마감 초는 동결한 첫 가설이다. 최적 수치로 검증됐다는 뜻은 아니다. 시간 만료는 **청산 요청의 시한**이다. 취소 지연·청산 주문 지연·호가 공백·깊이 부족 때문에 실제 가상 체결은 더 늦어진다. 손절가 체결을 보장하지 않는다.

## 비교 설계

| 정책 | 진입 대기 | 청산 |
|---|---:|---|
| `reference` | 기존 90초 | 추출한 B의 비용 게이트·정체·되돌림·돈 스탑 |
| `scalp_exit` | 기존 90초 | 새 무효화·60초 시간 제한·반대 속도 정체 |
| `scalp` | 5초 | `scalp_exit`와 동일 |

각각 `none`(외부 국면 필터 없음)과 `structure`(마감 구조 동의)를 실행한다. 정책별 자본은 독립적이지만 같은 입력과 동일한 위험·체결 가정을 사용한다. 노출을 동시에 합쳐 운용하는 포트폴리오가 아니다. 한 정책이 오래 보유하면 다음 진입을 놓치는 결과까지 포함한다.

`--scans`를 주면 완료된 `hunt-history`의 AI/결정론 방향만 쓰는 `recorded`/`recorded_det`도 추가한다. KST로 기록된 완료 초에 1초를 더한 뒤부터만 사용할 수 있고, 20분을 넘긴 스캔이나 다음 스캔에서 사라진 종목은 허용하지 않는다. 헌터의 자격·책 유지·퇴출·롱 급등 목표 매도를 전부 복원하지 않았으므로 **기존 B 전체 실거래 수익과 같은 것으로 읽지 않는다**.

첫 2시간 개발 실행의 5초 후보는 9회 주문·0회 체결이었다. 그래서 90초 진입 대기를 유지하는 `scalp_exit`를 별도 대조군으로 명시했다. 체결하지 않아 손실을 피한 결과를 짧은 청산의 효과로 해석할 수 없기 때문이다. 기준을 바꿔 성적을 끌어올리는 튜닝은 하지 않았다.

## 국내 실행 계약

현물 롱만 허용하며 가상 현금에서 재고 원가와 미체결 매수 예약금을 뺀 금액 이내로 주문한다. 자금 차입과 현물 숏은 없다. 5,000원 최소 주문 및 가격대별 호가 단위를 검사하고, 부분체결 후 잔고가 최소 주문 미만이면 잔고와 청산 불가 상태를 그대로 남긴다.

Coinone/Korbit 호가 단위는 종목별 공개 API 응답을 동결한다. Bithumb/Upbit는 확인한 원화 마켓 정책 표를 사용한다. 코인원의 역순 매도 호가와 거래소의 0수량 자리표시자는 정렬 전에 정규화한다. 빗썸 호가의 마이크로초 시각은 밀리초로 바꾸며 체결 방향과 고유 ID를 보존한다. 구독 때 받은 과거 체결·중복·늦은 체결을 신호로 누적하지 않는다.

국내 maker 모형은 도착 시점에 관측된 같은 가격의 대기 잔량을 앞에 둔다. 실제 반대 체결로 그 큐가 소모되거나 주문 가격을 넘어선 체결이 관측되어야 채우며, 체결량의 10%까지 참여한다. 호가에서 잔량이 사라지는 것만으로 체결하지 않는다. **실거래로 보정된 국내 체결 모형은 아직 아니다.** 낮은 체결률이 P&L의 하한이라는 보장도 없다.

| 거래소 | 기본 편도 요율 시나리오 | 추가 비교 |
|---|---:|---|
| 빗썸 | 0.04% 쿠폰, 무료 종료 이후를 기준 | 종료 시각을 반영한 `calendar`, 무쿠폰 0.25% `no_coupon` |
| 코인원 | 개인 API 무료 0% | 수수료 스트레스 하한 0.02% |
| 업비트 | 0.05% | 수수료 두 배 |
| 코빗 | 행사 0% | 가정 요율 0.06%; 확정된 행사 종료 요율이라는 뜻은 아님 |
| Bitget | maker 0.02%, taker 0.06% | 수수료 두 배 |

모든 스트레스는 주문 지연 1→2초, 추가 실행비용 5→30bp도 함께 적용한다. 지연과 슬리피지는 실측 확정값이 아닌 공통 비교 가정이다. 수수료는 주문 제출 시각에 동결하므로 행사 종료를 사이에 둔 주문/체결을 구분한다. 빗썸 무료 종료는 **2026-09-06 18:00 KST**이며, 계정의 쿠폰·행사 자격을 조회해 확인한 것은 아니다. [빗썸 종료 공지](https://feed.bithumb.com/notice/1654522), [원화 거래 정책](https://support.bithumb.com/hc/ko/articles/51036972377241), [코인원 종목별 호가](https://docs.coinone.co.kr/reference/range-unit), [업비트 원화 정책](https://docs.upbit.com/kr/docs/krw-market-info), [코빗 공개 데이터](https://docs.korbit.co.kr/llms/en/rest_api/quotation.md).

## 실행

레포 루트 PowerShell에서 실행한다. 출력은 매번 새 디렉터리를 지정한다.

```powershell
# 네 거래소, BTC/ETH/XRP/DOGE/SOL/TRUMP 중 거래 가능한 종목을 30분 수집.
# 공개 REST 마감봉으로 ATR·상위 구조를 준비하고 WS 흐름은 새로 워밍업한다.
python -u -m quant.collect --seconds 1800 --output data/quant/domestic-next

# 완성된 코인원 녹화를 재생. 다른 거래소도 같은 명령의 디렉터리만 바꾼다.
python -u -m quant compare data/quant/domestic-next/coinone/tape.jsonl --config data/quant/domestic-next/coinone/config.json --seed data/quant/domestic-next/coinone/seed.json --output data/quant/coinone-next

# 기존 Bitget 테이프와 당시 완료 스캔 비교.
$quantTapes = @((Get-ChildItem -Path 'data/ws/pub-20260904-1[8-9].jsonl.gz' | Sort-Object Name).FullName)
python -u -m quant compare @quantTapes --scans logs/hunt-history.jsonl --output data/quant/bitget-next

python -m unittest quant.test_pipeline quant.test_scalp
```

녹화는 API 키를 읽지 않고 주문 API를 호출하지 않는다. 24시간 이내의 유한 수집이며 연결 실패와 미완료 상태를 `capture.json`에 남긴다. 자동 재접속·프로세스 감시·장기 페이퍼 포지션 승계는 제공하지 않는다. 원본, 공개 계약/봉 응답, 수신 시각, 코드 해시를 저장한다. 거래소별 수집 시작에는 초기화 시간만큼 차이가 있으므로 거래소 간 정책 수익은 완전히 동시인 통제 실험으로 읽지 않는다.

`compare` 결과는 `report.md`, `results.json`, 정책별 `events-*.jsonl`, 코드/설정/원본 해시 `manifest.json`, 당시 Python 소스 사본 `source/`이다. 모든 비교와 실패는 `data/quant/trials.sqlite`에 개발 시도로 기록한다. 새 schema 2를 기존 v1 `replay/paper`에 넣어 국내 제약이 누락된 채 실행하는 것은 거부한다.

1/3/5/10/30/60초 진단은 두 종류다: 지연 뒤 시장가로 들어간 신호의 성적, 실제 가상 지정가 부분체결 뒤의 성적. 청산은 해당 지평 뒤 주문 지연을 더한 실제 호가 깊이의 VWAP와 수수료를 사용한다. 시한보다 1초 넘게 늦은 호가·깊이 부족·최소 주문 미만·미완성 지평은 검열한다. 같은 UTC 날짜·종목·방향의 무작위 대조도 남긴다. 서로 겹치는 표본을 독립 시행으로 세거나 펀딩 없는 선물 진단을 완전한 순손익으로 부르지 않는다.

`compare`의 판정은 개발 연구 `HOLD`다. 수익 우위·장기 데이터·독립 에피소드·전방 검증이 충족되기 전 실거래 승격 기능은 제공하지 않는다. 실제 실행 수치와 판단은 [SCALP-VALIDATION.md](SCALP-VALIDATION.md)에 기록한다.
